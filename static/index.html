Settings

Device identity & privacy

This browser has its own device identity. Chats, projects, memory, cloud-provider settings, MCP connections and workspace files are separated by device. Only the first owner device can manage worldwide tunnel credentials.

This device

Normal mode is the default and disables built-in filesystem and shell tools. Harness actions execute on the CanarryLookup host, not on the phone/browser computer. MCP integrations remain available; an MCP server may itself have external or system permissions. Harness mode is enabled only for this device identity.

Paired devices

Create a one-time pairing code for another browser or device. Codes expire after 10 minutes and can be used once.

Sign-in protectionNo password

Password-free access is the default for trusted home networks. Use a unique password of at least 16 characters before enabling a public connection.

Worldwide accessPUBLIC URL

Create a secure tunnel to this computer. Install the provider CLI first. ngrok uses your authtoken; Cloudflare supports Quick Tunnel or a named tunnel token plus hostname. Tailscale requires this host to be signed in and Funnel enabled.

No public connection established.

Public access requires a strong global username and password. Provider credentials are owner-device-only and are never returned to other devices. Keep the host running while remote devices connect.

Workspace behaviour

MCP tool servers — this device only

These MCP connections and credentials belong only to this device identity. Other paired devices cannot view or invoke them. Connect Model Context Protocol servers to expose their tools to Agent mode. Stdio launches a local process; Streamable HTTP connects to a configured MCP endpoint. Only add servers you trust: their tools may read files, access services or perform actions.

Long-term memory

Add concise facts or preferences you explicitly want retained. Memory is stored locally.

Uploads & privacy

Up to 20 files per turn, 50 MB per file. Text, PDF and DOCX content can be extracted. Images are passed to vision-capable models; binary files are stored but not interpreted. Image generation is available only through compatible image-generation APIs.
